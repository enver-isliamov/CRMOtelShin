# Спецификация: Синхронизация данных из UI в Google Sheets

## 1. Добавление нового клиента (Новый заказ)
- **Действие в UI:** Пользователь заполняет форму и нажимает "Сохранить".
- **Процесс в Vercel API:** 
  - Генерируется уникальный `id` (например, `c_1710672000000_1234`).
  - Клиент сохраняется в базу данных Postgres.
  - Отправляется вебхук `sync_client` в Google Apps Script (GAS).
- **Процесс в GAS:**
  - Скрипт ищет строку по `id` на листе `WebBase`.
  - Так как `id` новый, строка не находится.
  - Скрипт добавляет **новую строку** в конец листа `WebBase`.

## 2. Обновление существующего клиента
- **Действие в UI:** Пользователь редактирует данные клиента и сохраняет.
- **Процесс в Vercel API:**
  - Данные обновляются в базе Postgres по `id`.
  - Отправляется вебхук `sync_client` в GAS.
- **Процесс в GAS:**
  - Скрипт находит строку по `id` на листе `WebBase`.
  - Скрипт **обновляет существующую строку** новыми данными.

## 3. Истинная двусторонняя синхронизация (Исправление фоновой отправки)
- Ранее стандартный серверный fetch терял тело запроса при редиректах, используемых Google Apps Script. 
- **Решение:** Изменение функции `syncToGas` в `api/crm.ts` (использование `text/plain`, форсирование следования редиректам).
- Добавлена новая пакетная операция `sync_batch` в GAS, которая быстро и разом обновляет сотни записей (отсутствовавшие в UI клиенты заливаются обратно). При нажатии "Начать синхронизацию" происходит полный **Pull -> Push** цикл.

## 4. Сценарий: Завершение хранения (Выдача шин) и Быстрое переоформление
**Проблема:** Часто клиент забирает шины (не продлевает), и его нужно просто перенести в архив. Однако в следующем сезоне он может прийти с теми же шинами, и вводить заново все модели, размеры и состояние дисков — неудобно.

### Архитектура решения:
#### A) Завершить хранение (В архив)
- **Интерфейс:** В карточке активного клиента добавляется кнопка "Завершить хранение / Выдать шины".
- **Бэкенд:** Вызов нового endpoint'а. В базе `is_archived = TRUE`. 
- **Google Sheets:** Используется ранее добавленный процесс для копирования строки на лист `Archive` и её удаления с листа `WebBase`. Теперь таблица и UI остаются чистыми.

#### B) Быстрое переоформление из Архива ("Сдать снова")
- **Интерфейс:** Вкладка "Архив" (уже есть), в карточке архивированного заказа появляется кнопка "Оформить новое хранение".
- **Логика работы:**
  - Кнопка открывает стандартную форму добавления (`AddClient`), но **предзаполняет её данными из архива**.
  - **Копируется всё связанное с личностью и шинами:** ФИО, Телефон, Номер авто, Бренд_Модель, Размер шин, DOT-код, Наличие дисков, Кол-во шин, photoUrls.
  - **Очищается (нужно заполнить заново):** Номер договора (генерируется новый или пустой), Склад, Ячейка, Начало/Окончание срока, Оплаты/Долг.
  - Дальше процесс идет как обычное **Добавление нового клиента** (Создается новый `id`, строка падает в `WebBase`). Старая архивная запись остается нетронутой (сохраняя историю прошлых сделок).

## 3. Повторный заказ существующего клиента (Reorder)
- **Действие в UI:** Пользователь нажимает "Повторный заказ" (или "Переоформить").
- **Процесс в Vercel API:**
  - Создается новый объект клиента с **новым `id`**, но старыми ФИО, телефоном и авто.
  - В базе Postgres старый заказ помечается как `is_archived = TRUE`.
  - Новый заказ сохраняется как активный.
  - **Исправление (17.03.2026):** Ранее бэкенд ошибочно отправлял два `sync_client`, что приводило к дублированию строк в `WebBase`. Теперь бэкенд отправляет специальную команду `reorder` в GAS, передавая `oldClientId` и данные нового заказа.
- **Процесс в GAS:**
  - Скрипт получает команду `reorder`.
  - Находит строку старого заказа по `oldClientId` на листе `WebBase`.
  - **Копирует** данные этой строки и переносит их на лист `Archive` (с пометкой даты архивации).
  - **Обновляет** оригинальную строку на листе `WebBase` данными нового заказа (новый `id`, договор, даты и т.д.).
  - **Результат:** Таблица остается чистой. Старый заказ ушел в архив, а на его месте появился новый активный заказ.

## 4. Удаление клиента
- **Действие в UI:** Пользователь удаляет клиента.
- **Процесс в Vercel API:**
  - Клиент удаляется из базы Postgres.
  - Отправляется вебхук `sync_delete_client` в GAS.
- **Процесс в GAS:**
  - Скрипт находит строку по `id` на листе `WebBase` и **удаляет её**.
